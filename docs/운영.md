# 운영 안내서 — 배포·버전·PC 이전

이 문서는 **저장소만 봐서는 알 수 없는 것**을 적는다. 코드가 어떻게 동작하는지는 코드와
`README.md` 에 있고, 여기에는 **어디에 무엇이 올라가는지 · 무엇이 이 PC 에만 있는지 ·
PC 를 옮길 때 무엇을 챙겨야 하는지**를 적는다.

최종 갱신: 2026-09-09

---

## 1. 한눈에 — 배포하면 어디로 가는가

`배포.bat` (= `update.ps1 -Release -Publish`) 한 번이면 **다섯 곳**에 나간다.
순서가 정해져 있고, 이유가 있다.

| 순서 | 무엇을 | 어디에 | 왜 이 순서인가 |
|---|---|---|---|
| 1 | 공유 갤러리 사전 | Firebase `dict` | 앱보다 **먼저** 서 있어야 한다. 반대면 새 기체로 만든 구성이 잠깐 업로드 거부된다 |
| 2 | 데이터(OTA) | GitHub Release `data` | 폰이 실행 시 받아 간다 |
| 3 | PC 배포본·APK | GitHub Release `pc` | 링크로 배포 |
| 4 | 사이트 | Cloudflare Pages | 검사를 통과한 `dist\web` 을 직접 업로드 |
| 5 | 옛 주소 안내 | GitHub `gh-pages` | 4가 성공했을 때만 |

**앞 단계가 실패해도 뒤는 진행된다.** 곁가지 기능(사전·사이트)이 본체 배포를 죽이지
않도록 일부러 그렇게 짰다. 대신 실패하면 로그에 붉게 남으므로 배포 끝에 한 번 훑을 것.

## 2. 산출물 — 무엇이 몇 개인가

빌드는 **두 갈래**다. 같은 소스에서 나오지만 이미지 처리가 다르다.

### `node tools/build.js` — 오프라인판 (기본)

`dist/gbo2-simulator.html` · **15.87 MB** · 이미지 756장을 data URI 로 **인라인**

- APK · PC 경량판 · PC 완전판이 전부 이 파일 하나를 쓴다.
- `file://` 로 열리기 때문에 인라인이 **필수**다. 외부 이미지를 쓰면 캔버스가 오염돼
  PNG 카드 내보내기가 깨진다.

### `node tools/build.js --web` — 사이트판

`dist/web/index.html` · **8.47 MB** + `dist/web/images/` **7.2 MB** (756장)

- 사이트 전용. https 동일 출처라 캔버스 오염이 없다.
- 분리하는 이유는 두 가지다. base64 가 압축을 방해하고(전송 6.00MB → 1.23MB),
  `loading="lazy"` 가 무력화된다(첫 화면에 56장만 필요한데 756장을 받는다).
- `robots.txt` · `noindex` · `.nojekyll` 도 이때만 만들어진다.

### 배포 패키지 (`tools/build_release.js`)

| 산출물 | 크기 | 내용 |
|---|---|---|
| 경량판 `gbo2-simulator-pc.zip` | 13.5 MB | 앱 + `업데이트.bat` (GitHub 에서 데이터만 받음) |
| 완전판 `gbo2-simulator-pc-full.zip` | 57.3 MB | 위 + `node.exe` + `src`/`tools`/`data` (스스로 재빌드 가능) |
| APK `gbo2-simulator.apk` | 7.08 MB | 안드로이드 |

**중요**: `build_release.js` 는 `dist/` 를 통째로 담지 않고 **파일을 하나씩 골라** 담는다
(`gbo2-simulator.html`, `.apk` 둘뿐). 그래서 `dist/web/` 은 배포본에 안 들어간다.

## 3. 버전 — 스탬프 하나가 전부를 결정한다

**`build.js` 가 찍는 `stamp` 가 원본이다.** 형식은 `yyyy-MM-dd-HHmm` (분 단위, 로컬시각).

```
build.js  →  GBO2_BUILD.stamp  =  "2026-09-09-0950"
                    │
      update.ps1 이 빌드된 HTML 에서 읽어 온다
                    │
      ├── APK versionName
      ├── OTA version.json 의 "date"
      └── GitHub Release 'data' 의 릴리스 노트 ("데이터 2026-09-09-0950")
```

**배포 때 `Get-Date` 로 따로 찍으면 안 된다.** 예전에 그렇게 했다가 빌드와 몇 초 차이로
분(자정 근처면 날짜)이 어긋나, 앱이 아는 자기 버전과 배포된 버전이 달라졌다.

### 각 통로가 버전을 비교하는 방법

| 통로 | 내 버전 | 최신 버전 | 비교 |
|---|---|---|---|
| 폰(APK) | `SharedPreferences` 또는 `versionName` | Release 자산 `version.json` | 분 단위 |
| PC | `GBO2_BUILD.stamp` | Release **노트**(`api.github.com`) | 분 단위 |
| 사이트 | — | — | 새로고침이 곧 최신 |

PC 가 릴리스 **자산**이 아니라 **노트**를 읽는 이유: `file://` 에서 `releases/download`
는 CORS 로 막히는데 `api.github.com` 은 통과한다. 자산의 `updated_at` 은 날짜까지만
쓸 수 있어 같은 날 재배포를 못 잡았다.

## 4. 이 PC 에만 있는 것 ⚠️ — PC 이전의 핵심

저장소가 **공개**라 비밀값을 파일에 둘 수 없다. 그래서 아래 넷은 **저장소에 없다.**

### 4-1. 자격 증명 보관함

```
%LOCALAPPDATA%\gbo2-sim\
├── dict.cred    공유 갤러리 사전 계정 (이메일 + 비밀번호)
├── dict.sha     마지막으로 올린 사전의 해시 (바뀔 때만 올리려고)
└── site.cred    Cloudflare (Account ID + API 토큰)
```

**DPAPI 로 암호화돼 있어 복사해 가도 다른 PC·다른 Windows 계정에서는 안 풀린다.**
이건 결함이 아니라 의도다 — 파일이 새 나가도 남이 못 쓴다.

새 PC 에서는 **다시 등록**한다:

```powershell
.\update.ps1 -SetDictKey    # Firebase 사전 계정
.\update.ps1 -SetSiteKey    # Cloudflare
```

둘 다 **등록 직후 실제로 접속해 권한까지 확인**해 준다. 오타를 몇 주 뒤 배포 때 알게
되면 늦기 때문이다.

### 4-2. 나머지 셋

| 무엇 | 새 PC 에서 | 없으면 |
|---|---|---|
| `gh` CLI 로그인 | `gh auth login` | OTA·PC 배포본·옛주소 안내가 안 올라감 |
| JDK / Android SDK | `JAVA_HOME` 또는 Android Studio JBR | APK 를 못 만듦 |
| `wrangler` | `npm install --no-save wrangler` | 사이트가 안 올라감 |

`wrangler` 를 `package.json` 에 **일부러 안 넣었다** — 넣으면 완전판을 받은 사용자가
`npm install` 할 때 100MB 를 같이 받게 된다. 없으면 스크립트가 무엇을 실행하라고 알려 준다.

### 4-3. 새 PC 순서 요약

```powershell
git clone https://github.com/BaBoHoGu/gbo2_parts_simulator.git
cd gbo2_parts_simulator
npm install                        # jsdom · puppeteer-core (검증·위키 수신용)
npm install --no-save wrangler     # 사이트 배포용
gh auth login
.\update.ps1 -SetDictKey
.\update.ps1 -SetSiteKey           # Account ID: 163083f9c1502c19f706156a817584f2
.\update.ps1 -Rebuild              # 인터넷 수신 없이 빌드만 되는지 확인
```

마지막으로 **`-Publish` 없이** 한 번 돌려 보고, 로그에 붉은 줄이 없으면 배포해도 된다.

> 한글 경로 주의: 안드로이드 빌드가 한글 경로를 거부하므로
> `android/gradle.properties` 의 `android.overridePathCheck=true` 가 필요하다(이미 들어 있다).

## 6. 요금 — 왜 0원인가

셋 다 **결제 수단이 등록돼 있지 않다.** 한도를 넘으면 청구가 아니라 정지·연락이다.

| 서비스 | 한도 | 넘으면 |
|---|---|---|
| Firebase Spark | 저장 1GB · 월 다운로드 10GB | 그 달 동안 갤러리 정지 |
| Cloudflare Pages | 대역폭 **무제한** · 파일당 25MB | (배포 횟수 상한은 확인하지 않았다 — Git 연동 빌드는 월 500회로 알려져 있으나 우리는 Direct Upload 라 해당 여부가 불확실하다) |
| GitHub (공개 저장소) | Actions 무제한 · Pages 월 100GB(소프트) | 메일 연락, 심하면 사이트 정지 |

**Blaze(Firebase) 나 유료 플랜으로 올리지 말 것.** 올리는 순간 「정지」가 「청구」로 바뀐다.

### 여유 계산 (2026-09-09 실측 기준)

- 사이트 첫 방문 **1.23 MB** · 재방문 **0.78 MB**(브라우저 캐시가 이미지를 들고 있다)
- 갤러리 1회 열기: 구성 300건 기준 **268 KB** (300건을 넘어도 안 늘어난다 — 최근 300건만 받는다)
- 갤러리 저장: 구성 1건 916 B → **1GB 는 117만 건**. 올리기로 한도를 깰 방법은 없다.

Cloudflare 는 대역폭이 무제한이라 **사이트 쪽 사람 수 제한은 사실상 없다.** 먼저 걸리는 건
갤러리 읽기(월 10GB)인데, 1인당 월 10회 열어도 **약 3,900명**까지 간다.

## 7. 자동으로 도는 것

| 무엇 | 언제 | 어디에 |
|---|---|---|
| 공유 구성 백업 | **6시간마다** (GitHub Actions) | `share-backup/builds.json` |

비밀값이 필요 없다 — `builds`·`blocked` 는 공개 읽기다. **저장소 기본 권한이 `read` 여도
워크플로의 `permissions: contents: write` 가 먹는다**(실제 push 로 확인).

⚠️ **저장소에 60일간 활동이 없으면 GitHub 이 예약 워크플로를 자동으로 끈다.** 그때는
Actions 탭에서 한 번 눌러 다시 켠다.

**복구**: Firebase 콘솔 → Realtime Database → **`builds` 노드를 선택하고** ⋮ → JSON 가져오기.
**루트에서 가져오면 `dict` 를 포함해 전부 날아간다.**

## 7-2. 두 가지 배포 상황

실제로 배포하는 이유는 둘뿐이다. **명령은 같고, 갈라지는 건 사용자 쪽이다.**

### 케이스 A — 주간 게임 패치 (매주 목요일, 데이터가 바뀜)

```powershell
.\배포.bat          # = update.ps1 -Release -Publish
```

gbo2.jp·위키에서 변경분을 수집해 재빌드하고 다섯 곳에 올린다.

| 영역 | 동작 | 사용자 |
|---|---|---|
| APK | OTA 로 새 HTML | **껐다 켜기만** |
| 경량판 | `실행.bat` 이 열 때마다 확인·교체 | **평소대로 실행** |
| 완전판 | `update.bat` 이 직접 수집해 재빌드 | 배치 실행 |
| 사이트 | 새 `index.html` + **새로 생긴 이미지만** | **새로고침** |
| GitHub | Release `data`·`pc` 자산 교체 | — |
| **Firebase** | **새 기체·파츠가 생겼으면 `dict` 자동 재업로드** | — |
| Cloudflare | 바뀐 파일만 (같으면 0개·0.4초) | — |

**Firebase 가 이 케이스의 핵심이다.** 사전이 낡으면 새 기체로 만든 구성이 갤러리에
못 올라가고, 사용자에겐 「올릴 수 없는 구성」으로만 보인다. 이제 배포에 묶여 자동이다.

### 케이스 B — 프로그램 수정 (코드가 바뀜)

```powershell
.\update.ps1 -Rebuild -Release -Publish     # 수집 없이 재빌드만
```

| 영역 | 동작 | 사용자 |
|---|---|---|
| APK (JS 수정) | OTA 로 전달 | **껐다 켜기** |
| APK (`android/` 도 수정) | OTA 로 **안 감** | **⚠️ APK 덮어쓰기 설치** |
| 경량판 | 완성 HTML 을 받으므로 코드도 옴 | 평소대로 실행 |
| **완전판** | ⚠️ **코드 수정을 못 받는다** | **ZIP 을 새로 받아야 함** |
| 사이트 | `index.html` 1개만 | 새로고침 |
| Firebase | `변경 없음 — 건너뜁니다` | — |

`-Rebuild` 를 안 붙여도 결과는 같다(수집했는데 변경이 없을 뿐). 붙이면 몇 분 빠르다.

### ⚠️ 두 PC판이 정반대다 — 이름이 주는 인상과 반대

| | 데이터 | 코드 수정 |
|---|---|---|
| **경량판** — 완성 HTML 을 받는다 | ✅ | ✅ |
| **완전판** — 자기 `src/` 로 재빌드한다 | ✅ (직접 수집) | ❌ **못 받음** |

완전판이 더 자립적인 대신, **버그 수정이 자동으로 안 간다.** 새 ZIP 을 받아야 한다.
그래서 **권장은 경량판**이고, 공지에도 그렇게 쓴다.

## 8. 배포 전에 자동으로 도는 검사

실패하면 **배포가 중단된다.** 건너뛰지 말 것.

| 검사 | 항목 | 무엇을 잡나 |
|---|---|---|
| `tools/smoke.js` | 28 | 데이터·번역 누락, 이미지 존재, 스크립트 오류 |
| `tools/ui_check.js` | 181 | 실제 Chrome 4개 화면 크기 — 닫힌 모달이 앱을 덮음, 가로 스크롤, 안 눌리는 버튼 |
| APK 빌드 | — | 실패하면 **지난번 APK 가 배포된다** → 그래서 멈춘다 |

건너뛰는 스위치(`-NoSmoke`, `-NoUiCheck`, `-NoApk`)가 있지만 **쓰지 말 것.** 여기 있는
항목은 전부 예전에 실제로 배포까지 나갔던 사고들이다.

## 9. 자주 하는 실수

- **Firebase 콘솔의 「JSON 가져오기」를 루트에서 하지 말 것.** `dict`·`builds` 가 전부 날아간다.
  반드시 대상 노드를 먼저 선택한다.
- **콘솔에서 노드를 만들 때 값을 넣으면 잎 노드가 돼 자식을 못 단다.** 이름만 치고 그 줄의
  초록 `+` 로 자식을 만든다.
- **`-AsSecureString` 프롬프트는 입력해도 화면에 아무것도 안 보인다.** 붙여넣기가 안 먹어
  한 글자만 들어가도 「등록 완료」로 보인다. 지금은 20자 미만이면 저장을 거부한다.
- **`dist/web` 안에 `.git` 이 생기면 통째로 업로드된다**(6.7MB). 배포 스크립트가 매번 지운다.
- **속도를 한 번만 재고 단정하지 말 것.** GitHub Pages 가 79 KB/s 로 측정된 적도,
  2,773 KB/s 로 측정된 적도 있다. 실제로는 크게 요동친다. 사이트를 Cloudflare 로 옮긴
  근거는 「GitHub 이 느리다」가 아니라 **「Cloudflare 는 일정하다」**로 읽는 게 맞다
  (Cloudflare 는 여러 번 재도 0.27~0.36초로 붙어 있었다).
- **측정 대상을 잘못 잡지 말 것.** GitHub Releases 가 2 KB/s 로 나와 큰 문제인 줄 알았는데,
  자산 주소가 아니라 호스트 루트(`objects.githubusercontent.com/`)를 받아 오류 페이지를
  잰 것이었다. **제대로 재니 6,000 KB/s** 였다 — APK 7MB 가 1.2초, OTA 15.9MB 가 2.7초다.
  배포본 경로에는 문제가 없다.

## 9-2. 어디까지 자동인가 — 손이 가는 지점 넷

배포 자체는 `배포.bat` 한 번으로 다섯 곳이 전부 처리된다. 남은 수동은 넷뿐이고,
**셋은 구조상 자동화할 수 없다.**

| 지점 | 왜 수동인가 | 자동화 가능? |
|---|---|---|
| **배포를 누르는 것** | 목요일마다 사람이 실행 | ○ 작업 스케줄러로 가능 (아래) |
| **완전판의 코드 수정** | 자기 `src/` 로 재빌드하므로 새 코드를 받을 길이 없다 | △ 자기업데이트를 만들면 되지만 안 만들었다 |
| **`android/` 변경 시 APK 재설치** | 안드로이드가 앱 자체 교체를 앱에게 허용하지 않는다 | ✕ 불가 |
| **경량판을 `실행.bat` 이 아닌 HTML 로 직접 열 때** | 갱신 확인이 배치에 들어 있다 | ✕ 안내로만 해결 |

### 배포를 자동으로 돌리려면

`배포.bat` 을 Windows 작업 스케줄러에 목요일 저녁으로 걸면 된다. 다만 **권하지 않는다** —
배포 게이트(smoke·UI 181항목·APK)가 실패하면 멈추는데, 그걸 아무도 안 보고 지나가면
「배포된 줄 알았는데 안 된」 상태가 된다. 지금은 사람이 로그 끝을 훑는 것이 마지막 안전장치다.

굳이 건다면 `-Publish` 없이 **검사까지만** 자동으로 돌려 두고, 결과를 보고 사람이
게시하는 방식이 낫다.

## 10. 나중에 할 만한 것

- **폰 OTA 도 이미지 분리판을 쓰기.** APK 는 `file://` 이 아니라 자체 가상 주소
  (`https://gbo2.local`)로 서빙하므로 캔버스 오염이 없을 가능성이 크다. 그러면 갱신마다
  받는 양이 15.87MB → 0.9MB 가 된다. **확인 후에** 바꿀 것.
- **검색 노출.** 지금은 `robots.txt` 와 `noindex` 로 막아 뒀다. 열고 싶으면 둘을 빼면 된다.
  (한번 색인되면 되돌리기 어렵다는 점은 알고 결정할 것)
- **신고 기능.** `blocked` 노드는 있는데 사용자가 신고할 방법이 없다. 갤러리가 커지면
  이게 먼저 부담이 된다. 다만 **실사용이 쌓이기 전에 만들면 필요 없는 모양으로 만들게 된다.**
