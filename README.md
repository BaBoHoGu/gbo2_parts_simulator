# GBO2 커스텀 파츠 시뮬레이터 (오프라인)

[gbo2.jp](https://gbo2.jp/) 의 커스텀 파츠 시뮬레이터를 인터넷 연결 없이 쓸 수 있게
재구성한 것. 화면은 전부 한글이고, 원본에는 없는 **자동 파츠 구성**·**무장 피해 계산**·
**피탄 시뮬**·**공유 갤러리** 가 붙어 있다.

- 기체 1,715종 · 커스텀 파츠 163종 · 무장 3,800종 (gbo2.jp·위키 업데이트분 자동 반영)
- 계산 규칙은 원본 번들에서 그대로 이식 (슬롯·상한·강화리스트·확장 스킬·장착 제한)
- 서버도 설치도 필요 없음 — **HTML 파일 하나**가 전부다 (이미지까지 안에 들어 있다)

쓰는 곳은 셋이다. 어느 쪽이든 내용은 같다.

| | 주소 / 파일 | 갱신 |
|---|---|---|
| 웹 | https://gbo2-parts.pages.dev | 열면 항상 최신 |
| 폰 | `gbo2-simulator.apk` | 실행할 때 데이터 자동 수신(OTA) |
| PC | `dist/gbo2-simulator.html` | 경량판은 자동, 완전판은 스스로 재수집 |

## 사용법

`dist/gbo2-simulator.html` 을 더블클릭해서 브라우저로 열면 끝. **이미지까지 HTML 안에
들어 있어 파일 하나만 있으면 된다.** USB 에 넣어 다녀도, 메일로 보내도 그대로 동작한다.

화면은 세 칸으로 나뉜다. **왼쪽에서 기체를 고르고 → 가운데에서 결과를 보고 →
오른쪽에서 파츠를 붙인다.**

| 조작 | 동작 |
|---|---|
| 기체 카드 클릭 | 기체 선택 |
| 파츠 클릭 | 장착 / 해제 (장착 불가면 이유를 알려준다) |
| Shift + 클릭 | 파츠 설명 펼치기 |
| 우클릭 | 자동 구성에서 해당 파츠 제외 (다시 우클릭하면 해제) |
| 장착 타일 클릭 | 해제 |
| 🔒 | 자동 구성 시 그 파츠를 반드시 유지 |
| Esc | 열린 패널·결과 창 닫기 |

기체 목록은 이름 검색 외에 **속성 칩**(범용/강습/지원)과 **코스트 칩**으로 좁힐 수 있다.
파츠 목록은 지금 장착 가능한 것이 항상 위로 올라오고, 불가한 것은 흐리게 내려가며
"근접 슬롯 부족", "커넥팅 시스템 계열 중복" 같은 이유가 함께 표시된다.

## 한국어 표기

화면에 보이는 문자열은 전부 한글이다. 기체·파츠 이름은 물론 **무장명·무장 설명·스킬 글**까지
번역해 `data/i18n/` 에 사전으로 두고, 표시할 때만 치환한다. 계산은 항상 원본 일본어 키로
이루어지므로 원본과 결과가 어긋나지 않는다.

(사전 칸 수는 배포마다 늘어 여기 적지 않는다. 지금 값은 `node tools/dict_check.js` 가 찍는다.)

- 기체명·파츠명에 마우스를 올리면 원본 일본어 이름이 툴팁으로 뜬다 (게임/위키 대조용)
- 검색은 한글과 일본어 어느 쪽으로 쳐도 걸린다 ("자쿠" / "ザク" 둘 다 동작)
- 원본 데이터에 결합문자(`バ` = `ハ`+`゛`)가 섞여 있어 사전 조회는 NFC 정규화 후 수행한다
- 한국어 이름이 겹치는 기체는 뒤에 원문을 달아 가른다 (「카풀 - カプール」 / 「카풀 - カプル」)

**사전은 생성물이다.** `data/i18n/*.json` 을 손으로 고치지 말 것 — 다시 만들면 되돌아간다.
고칠 자리는 규칙(`tools/lib/glossary.js`)이나 용어표(`weapon_terms.json`)다.

## 기능

**시뮬레이터 (원본 이식)**

- 근접·중거리·원거리 슬롯 소비량과 상한 검사
- 강화리스트 단계(없음 / 4단계 / 풀강)에 따른 스탯·슬롯 보너스
- 확장 스킬 12종 × LV1~LV5 (장착 파츠 수에 비례하는 `パーツ拡張` 계열 포함)
- 스탯 상한 처리 — 기체별 상한 오버라이드, 파츠·강화리스트·확장·스킬의 상한 증가,
  상한에 걸린 항목은 노란색으로 표시. 공격 보정은 상한이 늘면 늘어난 만큼 피해에 반영
- 내구 지표(피해 종류별 실효 HP = HP / (1 − 내성/100)) 표시 — 원본 `耐久指標`과 동일 공식
- 장착 제한: 8개 제한, 동일 계열(`kind`) 중복, 스피드/선회 상승 파츠 배타,
  카테고리 특공 프로그램의 속성 제한, 기체 LV 비례 파츠, % 증가 파츠, ハロ（V） 속성 보너스
- 구성 저장/불러오기 — 이름을 붙여 여러 개 저장하고, 카드로 보며 불러오기·이름변경·삭제

**원본에 없는 것**

- **무장 피해 계산** — 사격·격투 보정·자세·스코프·파츠·스킬 반영, 격투 방향/연격,
  조사·산탄·동시발사는 전탄 명중 총 피해(×N) 표기. 적 내성 감소·실드 무시·집속 필수도 본다
- **피탄 시뮬** — 지금 구성이 적 무장에 몇 발 버티는지, 몇 발에 다운되는지
- **스킬 도감** — 기체가 가진 스킬을 한곳에서. 「계산 안 함」 보기로 **앱이 알고는 있지만
  숫자에 안 넣은 것 112종**을 고칠 수 있는가(29 / 65 / 18)로 갈라 보여 준다
- **공유 갤러리** — 만든 구성을 올리고 남의 구성을 받아 온다
- **토큰 계산기** — 픽업 일정과 함께
- **PNG 카드** — 구성을 이미지 한 장으로

**자동 구성**

원하는 방향만 정하면 규칙을 지키는 범위에서 가장 좋은 8파츠 조합을 알아서 찾는다.

- **프리셋**: 격투 강습 / 사격 지원 / 탱커 / 기동형 / 대빔 방어 / 대실탄 방어 / 밸런스
- **가중치**: 스탯별 상대적 중요도 (직접 조정 가능)
- **하한 목표**: "스피드는 최소 130" 같은 필수 조건. 달성 못 하면 어느 항목이
  얼마나 모자란지 알려준다 (상한이나 슬롯 때문에 애초에 불가능한 경우가 있다)
- **고정/제외**: 특정 파츠를 강제로 넣거나 후보에서 빼기
- **탐색 강도**: 빠름(4) / 보통(10) / 정밀(25) — 시작점 개수

탐색은 다중 시작점 + 최급상승 국소탐색이다. 매 이동마다 실제 계산 엔진을 돌려
점수를 매기므로, 상한에 걸려 낭비되는 조합은 자연히 배제된다. 근사 해법이라
탐색 강도를 올리면 결과가 더 좋아질 수 있다.

## 구조

```
raw/          gbo2.jp 원본(번들 JS·msData.json) · wiki/ 위키 캐시(~170MB, 커밋 안 함)
tools/
  update.js        데이터 자동 업데이트 (감지→수신→추출→번역→재빌드)
  gates.js         검사를 **전부** 돌린다 (동시 4개 · --fast 는 Chrome 없이 14초)
  build.js         src/ + data/ + assets/ → dist/  (--web 은 사이트판)
  build_release.js 자기 업데이트 가능한 배포 패키지(+node.exe) 생성
  fetch_wiki.js    기체별 위키 페이지 내려받기 (--pages=ID,ID)
  extract_weapons.js  위키 표 → 무장 데이터 (--merge)
  extract_ms_skills.js / find_buff_skills.js  위키 표 → 스킬
  auto_translate.js / translate_notes.js / translate_skills.js  신규분 온라인 번역
  build_weapon_i18n.js  무장명 한글 사전을 규칙으로 생성
  lib/glossary.js  MT 앞뒤로 게임 용어를 지킨다 (protect / post)
  lib/wikiwatch.js 새 기체를 **값이 굳을 때까지** 다시 받는다
  lib/janame.js    「한국어 - 원문」 꼬리표 규칙 (일본어 검사에서 봐 줄 자리)
data/         msData.json, parts.json, fullst.json, weapons.json, ms_skills.json …
  i18n/       ms · parts · weapons · weapon_note · skill_text · skills · weapon_terms
assets/images/  ms/ · parts/     (assets/missing.txt = 배포처에 이미지가 없는 기체)
assets/illust/  공식 일러스트 (사이트에만 올리고 앱은 URL 로 부른다)
src/          core.js(계산) damage.js(피해) optimizer.js(자동 구성) ui.js share.js token.js
dist/         gbo2-simulator.html ← **이미지까지 안에 든 단일 파일**
              web/ ← 사이트판(이미지 분리)
```

**이미지는 HTML 안에 넣는다**(data URI, 760장 5.55MB). `file://` 에서 외부 이미지는
캔버스를 오염시켜 PNG 카드가 깨지기 때문이다. 대신 사이트판(`--web`)은 이미지를 따로 내
압축이 듣고 `loading="lazy"` 가 살아난다.

## 데이터 자동 업데이트

원본이 갱신되면(신규 기체·파츠·밸런스 조정) **명령 한 줄로** 감지·수신·번역·재빌드까지 끝난다.

```powershell
.\update.ps1          # 자동 갱신 (+ 빠른 검사 14초)
.\update.ps1 -Check   # 감지만 하고 무엇이 바뀌는지 리포트
```

동작:

1. **감지** — `gbo2.jp/data/msData.json` 을 받아 로컬과 `MS名` 기준으로 비교한다.
   파츠·강화는 앱 번들을 받아 임시 추출해 **실제 내용을 대조**한다.
2. **수신** — 새/변경된 기체의 **위키 페이지만** 받는다. 여기에 더해:
   - **감시** — 새 기체는 위키가 틀만 먼저 만들고 며칠에 걸쳐 채우므로,
     **값이 두 번 연속 같아질 때까지** 다시 받는다. 안 그러면 덜 채워진 채로 굳는다.
   - **순회** — 감시에서 뗀 뒤에도 캐시가 가장 오래된 10개를 매번 돌아본다
     (601개면 60번에 한 바퀴). 오래된 캐시는 조용히 썩는다.
3. **추출·병합·번역** — 받은 페이지만 다시 뽑아 덮어쓰고, 새 이름·설명은 온라인 번역한다.
4. **재빌드** — 이미지(신규·변경분) → `build.js` 로 `dist/` 를 다시 만든다.
5. **검사** — `gates.js --fast` (Chrome 없이 14초). 걸리면 멈춘다.

## 배포

```
.\배포.bat        =  .\update.ps1 -Release -Publish
```

이 하나로 끝난다:

데이터 갱신 → APK 빌드 → **검사 30종**(약 4분) → 패치노트 초안 → 배포 ZIP 2종 →
GitHub OTA·APK 업로드 → Cloudflare Pages 게시 → **데이터 커밋·푸시**.

- **검사가 하나라도 걸리면 배포가 멈춘다.** 걸린 검사는 혼자 한 번 더 돌려
  부하 때문에 흔들린 것과 진짜 실패를 가른다.
- **커밋은 `data/` 만** 한다. `src/`·`tools/` 가 더러우면 작업 중인 코드라 손대지 않고
  알리기만 한다. 푸시는 원격에 이미 있는 브랜치일 때만.
- **패치노트 초안**은 이번 실행에서 실제로 바뀐 것만 적는다(수와 이름뿐 — 지어내지 않는다).
  사람이 오늘 자 절을 이미 썼으면 건드리지 않는다.

배포본은 둘이다.

| | 크기 | 갱신 방법 |
|---|---|---|
| 경량판 | 14MB | `업데이트.bat` 으로 GitHub 에서 데이터 수신 |
| 완전판 | 63MB | 내장 `node.exe` 로 **직접 수집·재빌드** (검사도 돈다) |

### 개발 PC 를 옮길 때

저장소만 옮기면 되는 게 아니다. **저장소에 없는 것**이 넷 있다 — 비밀값이거나 환경이라
공개 저장소에 둘 수 없어 일부러 PC 에 묶어 뒀다.

| 무엇 | 어디에 | 없으면 |
|---|---|---|
| `gh` CLI 로그인 | `gh auth login` | OTA·PC 배포본이 안 올라감 |
| Cloudflare 자격 증명 | `%LOCALAPPDATA%\gbo2-sim\site.cred` | 사이트가 안 올라감 |
| 공유 갤러리 시크릿 | Cloudflare 쪽에만 (`wrangler pages secret put`) | 갤러리 업로드가 거부됨 |
| JDK / Android SDK | `JAVA_HOME` 또는 Android Studio JBR | APK 를 못 만듦 |

`.cred` 는 DPAPI 로 **그 Windows 사용자에게** 암호화돼 있어 복사해 가도 안 풀린다.

```powershell
.\update.ps1 -SetSiteKey          # Cloudflare (등록 직후 실제 접속까지 확인해 준다)
npm install --no-save wrangler    # 사이트 배포 도구 (package.json 에 없다)
```

**전체 절차·계정·요금·자주 하는 실수는 [docs/운영.md](docs/운영.md) 에 정리돼 있다.**

## 검증

```
node tools/gates.js           검사 전부 (동시 4개, 약 4분)
node tools/gates.js --fast    Chrome·서버 안 쓰는 것만 (14초)
node tools/gates.js --jobs=1  하나씩 (로그를 순서대로 보고 싶을 때)
```

`tools/` 를 훑어 검사를 **주워 담는다** — 목록을 손으로 적지 않는다. 적으면 새로 만든
검사가 빠지고, 실제로 그렇게 빠진 검사가 잡았어야 할 버그가 배포까지 나갔다.

주워 담는 기준은 **파일 이름**이다(`*_check.js` · `check_*.js` · `smoke.js`).
그래서 아래 둘은 `gates` 가 안 돌린다 — 필요할 때 손으로 돌린다.

```
node tools/test.js    엔진 계산 + 자동 구성이 게임 규칙을 지키는지 (프리셋 7종 × 기체 3기)
node tools/shot.js    크로미움 스크린샷 (육안 확인용)
```

`font_scale_check.js`(전후 비교 도구)와 `vote_check.js`(구성 5개를 미리 올려야 하는데
업로드가 1분에 한 건)는 이유를 적어 `gates.js` 에서 **일부러** 뺐다.

주요 검사:

| 검사 | 보는 것 |
|---|---|
| `verify_against_original.js` | **원본 엔진과 직접 대조** — 스탯 30,000건 전수 일치 |
| `smoke.js` | 빌드 결과를 jsdom 으로 로드해 29개 항목 |
| `ui_check.js` | 실제 Chrome 4개 화면 크기 · 263개 항목 |
| `ja_leak_check.js` | 11개 화면·모달을 열어 **보이는 글자에 일본어가 남는지** |
| `dict_check.js` | 사전에 「null」·일본어가 박히지 않았는가 (Chrome 불필요) |
| `check_glossary.js` | 원문의 핵심어가 번역에 대응어로 살아 있는가 |
| `damage_path_check.js` · `part_effect_check.js` | 피해 경로 · 파츠를 끼워 수치가 바뀌는가 |
| `gallery_pw_check.js` | 로컬 서버를 띄워 갤러리 비밀번호 규칙을 실제로 시험 |

**원본 대조**가 계산 신뢰도의 근거다. `raw/app.js` 에서 원본 계산 함수와 의존성만 잘라내
Node 에서 실행하고, 같은 입력을 양쪽에 넣어 `total`·`rawTotal`·`base`·`partBonus`·
`fullStrengthenBonus`·`expansionBonus`·상한을 전부 비교한다.

```
node tools/extract_original_calc.js
node tools/verify_against_original.js 30000
```

## 알려진 차이

- 슬롯 보너스는 원본과 동일하게, 강화 단계(4/6)와 무관하게 강화리스트 전체를 더한다
  (스탯 계산은 4단계에서 앞 4개만). 슬롯 강화가 5·6번째 항목에 들어간
  `ギャプランTR-5_LV4`·`バウンド・ドック_LV2` 도 4단계에서 파츠칸이 늘어난다.
- `ペイルライダー［軽装備仕様］` 는 원본 사이트에도 이미지가 없어 기본 이미지로 대체된다.
- 원본에 있는 맵·랭킹 등 시뮬레이터 밖의 기능은 옮기지 않았다.

**일부러 넣지 않은 것** — 넣으면 오히려 실제와 멀어진다고 판단한 것들이다.
스킬 도감의 「계산 안 함」 보기에서 **무엇을 왜 안 넣었는지** 전부 볼 수 있다.

- 국부·거점·부위 보정 (자료가 23%뿐 — 전건을 못 채우면 두지 않는다)
- 비행형 슬러스터 (기체마다 거동이 달라 하나의 지표로 못 맞춘다)
- 조건부 피해 보너스 · 바리어 HP · 앵커류 사거리
