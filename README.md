# GBO2 커스텀 파츠 시뮬레이터 (오프라인)

[gbo2.jp](https://gbo2.jp/) 의 커스텀 파츠 시뮬레이터를 인터넷 연결 없이 쓸 수 있게
재구성한 것. 화면은 전부 한글이고, 원본에는 없는 **자동 파츠 구성** 기능이 붙어 있다.

- 기체 1,671종 · 커스텀 파츠 159종 · 이미지 741장
- 계산 규칙은 원본 번들에서 그대로 이식 (슬롯·상한·강화리스트·확장 스킬·장착 제한)
- 서버도 설치도 필요 없음

## 사용법

`dist/gbo2-simulator.html` 을 더블클릭해서 브라우저로 열면 끝.
**`dist/` 폴더 통째로**가 프로그램이다 (HTML 옆의 `images/` 에 기체·파츠 이미지가
들어 있다). USB에 폴더째 넣어 다녀도 그대로 동작한다.

화면은 세 칸으로 나뉜다. **왼쪽에서 기체를 고르고 → 가운데에서 결과를 보고 →
오른쪽에서 파츠를 붙인다.**

| 조작 | 동작 |
|---|---|
| 기체 카드 클릭 | 기체 선택 |
| 파츠 클릭 | 장착 / 해제 (장착 불가면 이유를 알려준다) |
| Shift + 클릭 | 파츠 설명 펼치기 |
| 우클릭 | 자동 구성에서 해당 파츠 제외 (다시 우클릭하면 해제) |
| 장착 타일 클릭 | 해제 |
| 🔒 | 자동 구성 시 그 파츠를 반드시 유지 |
| Esc | 자동 구성 패널 닫기 |

기체 목록은 이름 검색 외에 **속성 칩**(범용/강습/지원)과 **코스트 칩**으로 좁힐 수 있다.
파츠 목록은 지금 장착 가능한 것이 항상 위로 올라오고, 불가한 것은 흐리게 내려가며
"근접 슬롯 부족", "커넥팅 시스템 계열 중복" 같은 이유가 함께 표시된다.

## 한국어 표기

화면에 보이는 문자열은 전부 한글이다. 기체 583종, 파츠 159종과 그 설명문 전체를
번역해 `data/i18n/` 에 사전으로 두고, 표시할 때만 치환한다. 계산은 항상 원본
일본어 키로 이루어지므로 원본 사이트와 결과가 어긋나지 않는다.

- 기체명·파츠명에 마우스를 올리면 원본 일본어 이름이 툴팁으로 뜬다 (게임/위키 대조용)
- 검색은 한글과 일본어 어느 쪽으로 쳐도 걸린다 ("자쿠" / "ザク" 둘 다 동작)
- 원본 데이터에 결합문자(`バ` = `ハ`+`゛`)가 섞여 있어 사전 조회는 NFC 정규화 후 수행한다

## 기능

**시뮬레이터 (원본 이식)**

- 기체 1,671종 / 커스텀 파츠 159종
- 근접·중거리·원거리 슬롯 소비량과 상한 검사
- 강화리스트 단계(없음 / 4단계 / 풀강)에 따른 스탯·슬롯 보너스
- 확장 스킬 12종 × LV1~LV5 (장착 파츠 수에 비례하는 `パーツ拡張` 계열 포함)
- 스탯 상한 처리 — 기체별 상한 오버라이드, 파츠·강화리스트의 상한 증가,
  상한에 걸린 항목은 노란색으로 표시
- 장착 제한: 8개 제한, 동일 계열(`kind`) 중복, 스피드/선회 상승 파츠 배타,
  카테고리 특공 프로그램의 속성 제한, 기체 LV 비례 파츠, % 증가 파츠
- 구성 저장/불러오기 (브라우저 저장 + JSON 복사/붙여넣기)

**화면**

- 원본 사이트의 이미지를 함께 담았다 (기체 582장 + 파츠 159장). 기체 목록·장착
  슬롯·파츠 목록·선택한 기체가 모두 썸네일로 보인다
- 슬롯은 칸 게이지로 표시해 몇 칸이 남았는지 바로 보인다 (가득 차면 노란색)
- 성능표는 합계·증감·막대를 한 줄에 묶어, 소체분(회색) 위에 파츠로 늘어난 분(초록)이
  겹쳐 보인다. 상한에 닿으면 노란색으로 바뀐다
- 자동 구성은 오른쪽 패널로 분리해서, 평소 화면을 어지럽히지 않는다
- 좁은 화면에서는 한 칸으로 접힌다

**자동 구성 (추가 기능)**

원하는 방향만 정하면 규칙을 지키는 범위에서 가장 좋은 8파츠 조합을 알아서 찾는다.

- **프리셋**: 격투 강습 / 사격 지원 / 탱커 / 기동형 / 대빔 방어 / 대실탄 방어 / 밸런스
- **가중치**: 스탯별 상대적 중요도 (직접 조정 가능)
- **하한 목표**: "스피드는 최소 130" 같은 필수 조건. 달성 못 하면 어느 항목이
  얼마나 모자란지 알려준다 (상한이나 슬롯 때문에 애초에 불가능한 경우가 있다)
- **고정/제외**: 특정 파츠를 강제로 넣거나 후보에서 빼기
- **탐색 강도**: 빠름(4) / 보통(10) / 정밀(25) — 시작점 개수

탐색은 다중 시작점 + 최급상승 국소탐색이다. 매 이동마다 실제 계산 엔진을 돌려
점수를 매기므로, 상한에 걸려 낭비되는 조합은 자연히 배제된다. 근사 해법이라
탐색 강도를 올리면 결과가 더 좋아질 수 있다.

## 구조

```
raw/          gbo2.jp에서 받은 원본 (번들 JS, msData.json). remote/ 는 업데이트 감지용 임시본
tools/
  update.js        데이터 자동 업데이트 (감지→수신→추출→재빌드)
  build_release.js 자기 업데이트 가능한 배포 패키지(+node.exe) 생성
  extract_data.js  번들에서 파츠/강화리스트 데이터 추출 ([app.js] [outDir] 인자 가능)
  fetch_wiki.js    기체별 위키 페이지 내려받기 (--pages=ID,ID 로 일부만 가능)
  extract_weapons.js 위키 표 → 무장 데이터 (--merge 로 증분 병합)
  find_buff_skills.js 위키 표 → 버프 스킬 (--ui / --merge)
  fetch_images.js  기체·파츠 이미지 내려받기 (assets/images/)
  build.js         src/ + data/ + assets/ → dist/
  test.js          계산 엔진 + 최적화기 검증 (node)
  smoke.js         빌드 결과를 jsdom으로 로드해 27개 항목 검사
  extract_original_calc.js  원본 번들에서 계산 로직만 잘라내 _original_calc.js 생성
  verify_against_original.js 우리 엔진 vs 원본 엔진 대조 (무작위 구성 수만 건)
  shot.js          크로미움으로 열어 스크린샷 (shots/)
data/         msData.json, parts.json, fullst.json
  i18n/       ms.json(기체 583), parts.json(파츠명+설명 159), misc.json(속성·계열)
assets/images/  ms/ (582장 + _default), parts/ (159장 + _default)
src/          core.js(계산 엔진), optimizer.js(자동 구성), i18n.js, ui.js, style.css, index.html
dist/         gbo2-simulator.html + images/   ← 이 폴더째로 배포
```

이미지는 용량이 커서(5.4MB) HTML에 인라인하지 않고 옆 폴더에 둔다.
`<img>` 는 `file://` 에서도 상대 경로로 잘 읽히고, 지연 로딩이 걸려 있어
1,671기 목록을 스크롤해도 눈에 보이는 것만 읽는다.

## 다시 빌드하기

```bash
node tools/fetch_images.js   # 최초 1회: assets/images/ 채우기
node tools/build.js          # dist/ 생성
node tools/test.js           # 엔진/최적화기 검증
npm i --no-save jsdom && node tools/smoke.js       # 27개 항목 자동 검사
npm i --no-save puppeteer && node tools/shot.js    # 스크린샷으로 육안 확인
```

## 데이터 자동 업데이트

원본이 갱신되면(신규 기체·파츠·밸런스 조정) **명령 한 줄로** 감지·수신·재빌드까지 끝난다.

```bash
node tools/update.js            # 감지 → 변경 있으면 받기·추출·재빌드
node tools/update.js --check    # 감지만 하고 무엇이 바뀌는지 리포트 (반영 안 함)
```

Windows 에서는 PowerShell 진입점을 쓴다 (아래 "배포" 참고).

```powershell
.\update.ps1          # 자동 갱신
.\update.ps1 -Check   # 미리보기
```

동작:

1. **감지** — `gbo2.jp/data/msData.json` 을 받아 로컬과 `MS名` 기준으로 비교한다
   (신규·삭제·스탯 변경). 파츠·강화는 앱 번들(`/assets/index-*.js`)을 받아 임시로
   추출해 `parts.json`/`fullst.json` 과 **실제 내용을 대조**한다.
2. **수신** — 새/변경된 기체의 **위키 페이지만** 받는다 (`fetch_wiki --pages=ID,ID`).
   변경된 기체는 캐시를 지워 다시 받고, 신규는 캐시에 없어 자동으로 받는다.
3. **추출·병합** — `extract_weapons --merge` / `find_buff_skills --merge` 가 받은
   페이지만 다시 뽑아 기존 데이터에 덮어쓴다 (위키 캐시 172MB 전체 없이도 동작).
4. **재빌드** — 이미지(신규만) → `build.js` 로 `dist/` 를 다시 만든다.

변경 종류에 따라 필요한 단계만 돈다 (파츠만 바뀌면 위키는 건드리지 않음).

> **새 기체 한글명** 은 자동 번역되지 않는다(음역 사전에 기체 용어가 없음). 업데이트가
> 끝나면 `data/i18n/ms.json` 에 추가할 이름을 리포트로 알려준다. 사전에 없으면 원본
> 일본어가 그대로 표시되며, 성능·무장 계산에는 지장이 없다. 무장명은 자동 음역된다.

## 배포

`dist/` 만 넘겨도 시뮬레이터는 돌지만, **받은 사람이 직접 업데이트까지 하려면** 갱신
파이프라인과 실행 런타임을 함께 담아야 한다. 이를 자동으로 묶어 준다.

```bash
node tools/build_release.js   # release/<이름>/ 폴더 + 같은 이름 .zip
```

- 개발 저장소와 **같은 레이아웃**(`dist/` + `assets/images` + `src` + `tools` + `data`)에
  **`update.ps1` 과 내장 `node.exe`** 를 함께 담는다 (약 44MB zip).
- 받은 사람은 아무것도 설치하지 않고 `update.ps1` 실행만으로 최신 데이터를 받는다.
  `update.ps1` 은 동봉된 `node\node.exe` 를 먼저 쓰고, 없으면 시스템 `node` 로 넘어간다.
- 사용자는 `dist\gbo2-simulator.html` 을 연다. 폴더 구성은 그대로 두어야 한다.

## 알려진 차이

- 원본은 슬롯 보너스를 계산할 때 강화리스트 단계와 무관하게 6개 항목을 모두
  더한다. 여기서는 스탯 계산과 동일하게 4단계에서는 앞 4개만 반영한다.
  `verify_against_original.js` 로 전수 대조한 결과 이 차이가 나는 기체는
  **`ギャプランTR-5_LV4`, `バウンド・ドック_LV2` 2기뿐**이고(0단계·6단계는 완전 일치),
  스탯 계산에는 영향이 없다.
- 파츠 설명문의 부가 효과(리로드 단축, 피해 경감률 등)는 원본과 마찬가지로
  수치 계산에 반영되지 않는다. 표시만 된다.
- `ペイルライダー［軽装備仕様］` 는 원본 사이트에도 이미지가 없어 기본 이미지로
  대체된다. 이미지가 없는 항목은 `assets/missing.txt` 에 기록된다.
- 원본에 있는 맵·랭킹 등 시뮬레이터 밖의 기능은 옮기지 않았다.

## 검증

```
node tools/test.js    엔진 계산 + 자동 구성 결과가 게임 규칙을 지키는지 (프리셋 7종 × 기체 3기)
node tools/smoke.js   빌드 결과를 실제로 로드해 27개 항목 검사
node tools/shot.js    크로미움 스크린샷 (육안 확인용)

node tools/extract_original_calc.js       # raw/app.js 에서 원본 계산 로직 추출
node tools/verify_against_original.js 30000   # 원본 엔진과 직접 대조
```

**원본 대조**가 계산 신뢰도의 근거다. `raw/app.js` 에서 원본 계산 함수(스탯·슬롯)와 그
의존성만 잘라내 Node 에서 실행하고, 같은 입력(기체 × 강화단계 × 확장스킬 × 무작위 구성)을
양쪽에 넣어 `total`·`rawTotal`·`base`·`partBonus`·`fullStrengthenBonus`·`expansionBonus`·
상한을 전부 비교한다. 현재 **스탯 30,000건 전수 일치**.

`smoke.js` 가 보는 것: 스크립트 오류, 초기 렌더(카드·썸네일·슬롯·스탯 11행),
속성/코스트 필터, 한국어·일본어 검색, 파츠 장착 반영, 자동 구성 실행과 슬롯 초과 여부,
화면에 남은 일본어, 사전 전수 번역, 참조하는 이미지 파일의 실제 존재 여부.
